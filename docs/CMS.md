# MathLab — керування контентом

## Перший етап: Git-backed CMS

Публічний сайт як і раніше працює на Next.js / Vinext із серверним `/api/lead`. Нову незахищену сторінку `/admin` **не створювали**.

- `content/site.json` — редаговані дані головної сторінки: SEO, контакти, CTA, програми, етапи, переваги, FAQ, зображення.
- `.pages.yml` — конфігурація [Pages CMS](https://pagescms.org/) для цих полів.
- `app/page.tsx`, `app/layout.tsx` — споживають спільні дані, а не дублюють тексти в компонентах.
- `tests/content-config.test.mjs` — перевірка базової структури даних.

### Як відкрити редактор

1. Перейдіть на https://app.pagescms.org і увійдіть через GitHub.
2. Інсталюйте або авторизуйте Pages CMS GitHub App з доступом до репозиторію `SmychenkoOleg/tutor.zp.ua`.
3. Виберіть репозиторій та гілку, до якої додано ці файли.
4. Відкрийте **MathLab — вміст сайту** і відредагуйте потрібну секцію.
5. CMS створює Git-коміт; зміни на сайті з'являться тільки якщо налаштовано процес збірки й публікації відповідної гілки.

> Pages CMS — сторонній GitHub-додаток: надання доступу до репозиторію потребує дії власника. Не передавайте CMS токени Telegram, паролі чи особисті дані клієнтів.

### Безпека та межі першого етапу

- Доступ до CMS контролює GitHub/Pages CMS, а не сам вебсайт. Публічний `/admin` відсутній.
- **Заявки містять персональні дані і не повинні зберігатися в Git.** Серверний обробник заявок не змінювався.
- Модерація відгуків, база Cloudflare D1 і захищений кабінет для перегляду заявок — окремий етап із власною авторизацією.
- Приватну політику, cookie-банер та налаштування GTM цей етап не змінює.
- `content/site.json` — контрольований файл, не використовуйте HTML/скрипти у звичайних текстових полях.

### Перевірка

```bash
node --test tests/content-config.test.mjs
```

Для запуску й збірки використовуйте оригінальні скрипти проєкту та сумісне середовище, описане в `README.md`.
